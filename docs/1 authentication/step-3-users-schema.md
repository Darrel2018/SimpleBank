# Step 3 — Users Collection Schema

## Purpose

The `users` collection stores authentication and authorization information for every user who can access SimpleBank.

It is the authentication identity of the application and is intentionally separated from banking information such as accounts, balances, and transactions.

## Version 1 Schema

| Field            | Type             | Description                                                           |
| ---------------- | ---------------- | --------------------------------------------------------------------- |
| `_id`            | ObjectId         | MongoDB primary identifier.                                           |
| `first_name`     | String           | Customer first name.                                                  |
| `last_name`      | String           | Customer last name.                                                   |
| `email`          | String           | Unique login email address.                                           |
| `phone`          | String           | Customer phone number.                                                |
| `password_hash`  | String           | Secure hashed password generated by Django.                           |
| `role`           | String           | `customer`, `business_customer`, `employee`, or `admin`.              |
| `status`         | String           | `pending_verification`, `active`, `suspended`, `frozen`, or `closed`. |
| `mfa_enabled`    | Boolean          | Indicates whether OTP is required after login.                        |
| `email_verified` | Boolean          | Indicates whether registration has been verified.                     |
| `created_at`     | DateTime         | Account creation timestamp.                                           |
| `updated_at`     | DateTime         | Last update timestamp.                                                |
| `last_login`     | DateTime or Null | Last successful login timestamp.                                      |

## Registration Defaults

A newly registered customer should receive:

* `role = "customer"`
* `status = "pending_verification"`
* `mfa_enabled = true`
* `email_verified = false`
* `last_login = null`

## Security Principles

* Never store plain-text passwords.
* Never store government IDs, passports, selfies, or banking credentials.
* Authentication data lives in `users`; financial data lives in separate collections.
